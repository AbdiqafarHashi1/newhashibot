## Architecture and workload placement

One Node 24 worker image runs one bounded slice as a Cloud Run **Job**, then exits. There is no request-dependent background loop and no five-service split. Supabase remains database, Auth, commerce and execution authority. A short `phase-p-workers` authenticated Edge request validates a closed typed request, freezes canonical lineage and calls the atomic enqueue RPC. It performs no heavy computation. The existing Backtest controls queue replay/account/Prop work; the added panel queues public crypto history and offers authenticated inspect/details/export/stop/resume/cancel/retry controls. Both submission panels have synchronous pending locks and disabled pending controls.

Placement labels describe separate facts:

- `CONNECTED_LOCAL`: concrete entry point, handler, transport/store and authenticated operational control exist; local execution or injected transport tests exercise that path.
- `RETAINED_ON_SUPABASE`: the existing phase owns its queue, lease, checkpoint and side-effect authority. No cloud migration is claimed.
- `PREPARED_FOR_CLOUD`: that selected portable workload is packaged in the single image and dormant Terraform Job.
- `EXTERNALLY_CONFIGURED`: configuration has been supplied and independently verified. Here it is **NO** for every cloud workload.
- `DEPLOYED`: runtime activation was actually performed. Here it is **NO** throughout.
- `GENUINELY_TESTED`: the named test scope actually ran. It does not mean external end-to-end validation; see the last column.

## Durable runtime and limits

`portable_jobs` is extended, not replaced. Claim locks the shared control row and atomically reserves quota, selects one eligible job with `FOR UPDATE SKIP LOCKED`, increments attempts/slices, and assigns a fresh lease token. Global heavy-work concurrency is one across portable invocations. Leases last 90 seconds; a worker slice is at most 45 seconds, transport requests are timed out, and Cloud Run timeout is 60 seconds. Heartbeat, evidence append, checkpoint and completion require the current token, RUNNING status, unexpired lease, uncancelled native run, current admin role and matching customer/account ownership. Native evidence and the cursor commit in one transaction. Expired workers cannot heartbeat, append, complete, retry or advance a reclaimed job.

Each handler uses concrete stores. Replay checkpoints its event cursor and active/last-signal scanner-selection state alongside each native cycle/outcome. Account checkpoints the shared Phase-D simulation cursor, balance, equity and lock state alongside each native decision. Prop checkpoints each completed professional challenge window and resumes at the next window. Completed computation prefixes are not recomputed. An interrupted in-progress replay outcome or Prop window may restart, but its work is bounded by 3,000 outcome candles or 500 source trades, and explicit shared-engine steps yield to cancellation, shutdown and deadlines. The professional first-passing search now steps the same accumulated challenge state linearly rather than repeatedly simulating every prefix; full golden results from source main remain identical. No alternative trading engine, risk rule or quantity formula was added. Replay stops evaluation before the last available forward candle and reports `evaluationEnd`, `requestedEnd` and `FORWARD_CANDLE_REQUIRED`. History persists pages before advancing and detects conflicting duplicate candle content. Native evidence is immutable. Customer/account/run/configuration/job lineage is protected from changes by a trigger.

Cancellation locks the job and cancels its native run in the same transaction. Completion similarly commits native completion and job completion together. Retry delay is bounded exponential backoff; three failed attempts or 40 total slices lead to dead letter and failed native evidence state. Successful yields release ownership and do not consume a failure attempt. Dead letters cannot be resurrected through the UI; inspect safe failure and submit a new authorized run. Stop-new-work blocks admission/claim while preserving cancellation, reconciliation reads, timeout/dead-letter recovery and existing retained protection duties.

Hard portable bounds: 4 datasets/symbol contexts, 3,000 candles per dataset, 12 history pages, 500 validation cycles/account points/Prop source trades, 250 candles per history checkpoint; one computed cycle, Account decision or Prop window per fenced checkpoint, one heavy job, 45-second slice, three attempts, 40 slices/job, 20 submissions and 100 slices/customer/UTC day. The control table allows daily quotas to be lowered. Submission and slice reservations are atomic. Quotas count reservations/attempted work, not actual Google billing. AI tokens/spend and cloud artifacts are zero: this worker has no AI, generation, delivery or Storage transport. Existing Phase-O artifact retention and AI approval budgets remain its authority; no new cloud retention claim is made.

There is no five-service permanent background loop. A Job runs `HASHIBOT_WORKER_MODE=once`, claims at most one slice, and exits. Diagnostic `check` validates configuration without consuming work; `health` exposes `/health` and consumes no work. The `check` result explicitly says `CONFIGURATION_ONLY`. Diagnostic `health` performs timed, read-only PostgREST probes of the control, queue and native evidence schema: it returns `DATABASE_READY` only when those probes succeed, `DATABASE_UNAVAILABLE` with HTTP 503 on failure, or `CONFIGURATION_ONLY` when database credentials are absent. It performs no claim or mutation; RPC availability is additionally checked during the real local connected pipeline and on claim. Missing schema fails closed. SIGTERM/SIGINT abort transport and computation checks; a terminated process that cannot finalize is recovered by lease expiry. A container health check explicitly uses `check` so it never consumes a second job.

Only the durable queue owns retries. Immutable image digest is required. Terraform resources default to absent (`deployment_enabled=false`); worker consumption separately defaults off. There is no public invoker, Scheduler resource, execution service, VPC/NAT expense, enabled API or billing mutation. Overlapping executions can still start and incur startup charges; the database prevents simultaneous heavy work. Future invocation frequency must be bounded by the authorized invoker/orchestrator.

External configuration requires project/region, immutable image digest/revision, pre-enabled Run/Artifact Registry/Secret Manager APIs, approved server credential reference and Supabase URL, project permissions for an authorized deployer, and owner-controlled private invocation. The worker reuses the existing approved Supabase server credential; customer provider secrets remain in the existing Vault/provider boundary. Google IAM is secret-scoped; Supabase's reused service credential is privileged and must never enter the browser. A narrower database gateway/credential would need separately approved implementation; this phase does not pretend the service credential is table-scoped.

The source defaults delivery, AI, demo dispatch, schedules and live execution to disabled, refuses explicit enabling in the worker environment, and never routes those operations. Legacy cloud deploy/push/apply/destroy/rollback/remote verification scripts now refuse action rather than reference absent five-service manifests. The handoff below is the preparation authority.

### Repair details

Approved configuration retains empty allowed-symbol lists as the production unrestricted meaning. One stable contract-ordered snapshot covers all selected symbol/timeframe/market contexts, preserves explicit restrictions, versions and parameters, sorts restriction sets/parameter keys, and validates every selection before enqueue. Dataset IDs are normalized and sorted; unsupported or duplicate symbol/timeframe selections fail explicitly.

Attempt keys are written to durable browser storage before sending and scoped by actual authenticated user, task kind and normalized immutable selection. Uncertain responses and refresh/retry retain the key. Changed selections and explicit New run controls allocate a new key; user changes cannot share a key. Pending promises and synchronous UI refs collapse rapid repeated clicks. The server validates an existing accepted selection and reuses its frozen payload rather than rebuilding changed approvals; the atomic queue RPC creates neither another run nor another quota reservation for a duplicate.

Deadline/shutdown interruptions yield rather than exhausting a failure attempt. Cancellation/lease loss during computation or finalization cannot complete or retry a cancelled run. Substantial Replay outcome and Prop evaluation loops expose interruptible steps; Account resumes exact Phase-D state. Durable native evidence remains the final details/export and summary authority.
