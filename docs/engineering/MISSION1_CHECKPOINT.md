## Runtime and implemented changes

The active production route is `scheduled-market-scanner` → `market-scanner` → `watched-strategy-discovery` → existing named evaluators → `entry-decision` → existing transactional watch/signal/outbox authority. `conditional-watch` independently reloads persisted watches and uses the same decision, frozen evaluator, regime, and release contracts. Pausing the canonical engine does not select the retained legacy scanner. Compatibility code remains for prior paper records/replay, not as an alternate production entry engine.

1. **IMPLEMENTED / TESTED:** `entry-decision.ts` emits one identity-bearing IMMEDIATE_CONFIRMED, CONDITIONAL_WATCH, or NO_TRADE object with closed-data timestamps, net reward/risk, regime, qualification and diagnostics. Complete named confirmations inside the original entry zone enter immediately. Unsuitable, stale, malformed and unqualified opportunities record genuine admin diagnostics.
2. **IMPLEMENTED / TESTED:** `watched-strategy-discovery.ts` preserves original parameters, configuration hash, evidence, zone, trigger, risk plan, source, expiry and track. MicroScalper's specific incomplete-body failure is watchable only when its other exposed named gates pass. Arbitrary strategy rejection is never relabeled as a credible setup.
3. **IMPLEMENTED / TESTED:** `frozen-strategy-confirmation.ts` resolves the original named evaluator/version/parameters. Fresh confirmation evidence records the exact closed bar, configuration hash and evaluator result. Current catalog qualification is rechecked, including revocation/replacement/disablement. Changed frozen conditions never rescue an opportunity.
4. **IMPLEMENTED / TESTED:** `conditional-signal-runtime.ts`, `conditional-signal-service.ts`, `conditional-watch.ts` load all bounded open watches, retain missing-data/source-gap watches for recovery, expire by wall clock without inventing candles, enforce closed-trigger and entry-chase/cost checks, and use CAS. Watch outcomes CONFIRMED/INVALIDATED/EXPIRED are latched separately from subsequent paper-position management; filled-position protection is not cancelled by a later release revocation.
5. **IMPLEMENTED / TESTED:** `20261104224012_mission1_entry_lifecycle.sql` preserves immutable origin, terminal fences, entry evidence, history and outbox atomicity. Both new-policy immediate and conditional entries require successful measured signal projection inside the transaction. Replays do not create another signal/event; revoked or mismatched release projection rolls back. Worker grants are explicit rather than assumed from platform defaults.
6. **IMPLEMENTED / TESTED:** Free conditional follow-ups require an exact persisted preselected sample/state/version. The canonical outbox is the real production implementation in the combined SQL tests. Telegram payloads and customer execution share the projected confirmed signal ID. Unknown Telegram send receipts remain reconciliation work, not blind resends.
7. **IMPLEMENTED / TESTED:** `entry-regime.ts` reuses the causal classifier and distinguishes uptrend, downtrend, range, compression, expansion, transition, abnormal and insufficient-data states. Family/direction eligibility is enforced. `conditional-market.ts` has explicit modeled asset liquidity reserves and FX/JPY/Gold cost units. 8. **IMPLEMENTED / TESTED:** Existing root arbitration, database symbol ownership and per-account risk/capital/entitlement gates remain authoritative. Losing/opposing/atomic admission rejections are recorded. `portfolio-exposure.ts` adds a conservative account-level shared-factor budget for Crypto and FX/Gold currencies; opposite trades are not assumed to hedge. Admin controls may narrow `maxCorrelatedRiskPct`, never expand portfolio policy. There is no arbitrary three-position Swing cap; 15m Swing retains its own track.

The existing registry passes definition-specific research parameters. Explicit registry identities support specialist release resolution without a second strategy-name registry.
10. **IMPLEMENTED / TESTED:** `ConditionalSignalsPanel.tsx` reads genuine decisions/reasons, immediate counts, watch resolution, history, feed/worker health and signal projection eligibility. No performance metrics are fabricated. The Backtest Lab is preserved.
